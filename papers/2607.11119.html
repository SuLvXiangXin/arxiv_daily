VIA: Visual Interface Agent for Robot Control

arXiv: 2607.11119 作者: Dorsa Sadigh Team 日期: 2026-07-13

📝 详细解读

研究背景与动机

机器人操作是一个复杂的任务，需要视觉理解、物理推理、规划和闭环控制。通用基础模型在视觉感知和推理方面表现突出，因此利用它们实现通用机器人策略极具吸引力。当前主流方法是将现有基础模型转化为视觉-语言-动作模型（VLA），通过对机器人数据进行微调来输出低级动作。然而，受限于可用于微调的计算和机器人数据规模，VLA模型的参数量往往比前沿的基础模型小数个数量级，这限制了其通用能力，特别是在物理推理和长视距规划方面。另一类范式是“代码即策略”，即提示基础模型生成调用预设感知API和人工设计技能原语的代码。尽管这利用了模型的强大编程能力，但系统性能往往受限于人工设计的抽象层，当用低级原语替代高级原语时，成功率会急剧下降。

本文针对“如何在不进行机器人特定微调的前提下，利用最强大的前沿基础模型进行机器人控制”这一痛点，提出了一个新视角：将机器人控制重新定义为智能体的一项视觉工具使用任务，类似于通用的计算机操作。核心思路是：设计一个人类可读的视觉界面和工具集，让现成的、未经机器人数据调整的通用AI代理，通过观察、规划和执行闭环，像操作软件一样控制机器人。

方法详解

VIA框架的核心是将机器人控制重构为一个基于视觉界面的智能体观察_______操作循环。一个通用代理操作一个基于浏览器的3D机器人控制界面：它截取界面截图，根据所见进行推理，通过直观的模型上下文协议工具发出指令，观察结果并调整，循环直到任务完成或超时。代理仅能感知界面渲染的内容，无法访问模拟器的特权状态，也不依赖任何感知辅助API（如分割函数）。

整体流程基于一个浏览器界面，该界面从多视角RGB-D摄像头重建出3D点云作为主工作区，并同时显示固定的第三人称和腕部摄像头原始视图。代理通过screenshot工具观察整个界面。通过一系列MCP工具（如gripper_teleport_via_click， gripper_translate等）在主工作区中设置一个蓝色虚拟“目标夹具”的6自由度位姿（路径点）。一旦对路径点满意，代理调用execute_waypoint工具，触发一个简单的PI控制器，通过线性插值将真实夹具移动到目标位姿。执行后，代理再次截图观察结果，并开始规划下一个路径点。

图1：VIA框架概览。一个现成的代理通过基于浏览器的3D界面控制机器人。界面包含由RGB-D摄像头重建的3D点云场景，以及原始的第三人称和腕部摄像头画面。代理通过人类可读的MCP工具（如截图和控制虚拟目标夹具）进行观察和行动。

核心模块是围绕界面交互设计的一套MCP工具集，分为四类：

  1. 观察工具：如screenshot（获取界面截图）、hover（获取点击位置的3D坐标）、gripper_show_rotation_gizmo（显示旋转操纵器辅助理解）。
  2. 动作工具：用于操纵虚拟目标夹具，如gripper_teleport_via_click（点击传送）、gripper_translate（键盘精确平移）、gripper_rotate（键盘精确旋转）、gripper_toggle（开合夹具）。这些工具仅改变界面上的虚拟夹具状态，不影响真实机器人。
  3. 摄像头工具：如camera_orbit_via_key、camera_pan_via_key、camera_zoom，用于改变3D工作区的视点，以便从不同角度观察场景。
  4. 执行工具：execute_waypoint（执行当前路径点，移动真实机器人）、end_episode（结束回合）。

图2：VIA控制循环的一个回合，以开抽屉任务为例。上半部分（操作）：代理通过一系列工具调用设置下一个路径点，例如在查看其旋转操纵器后调整目标夹具方向，然后点击将其传送至抽屉把手。每次工具调用都会返回更新后的截图，因此代理在发出下一个操作前会检查效果。下半部分（执行）：execute_waypoint将路径点交给控制器，控制器移动真实机器人。然后代理重复此循环（左箭头所示）。

与现有方法相比，VIA的创新点具体体现在：1）完全避免了针对机器人数据的模型微调，直接利用通用代理及其底层基础模型的现成能力；2）提供了一套低抽象层次、人类可读的工具，而非生成代码或输出底层动作，将感知和推理任务完全交给代理；3）将机器人环境呈现为一个通用系统（智能体）可以感知和操作的界面，使得计算机操作智能体的技术进步能够直接迁移到机器人控制。

实验与结果

实验设置：实验在robosuite模拟器中进行。使用了六个多样化的桌面操作任务进行评估：堆叠（Stack）、打开炉灶（Turn on stove）、开抽屉（Open drawer）、将碗放在盘子上（Put bowl on plate）、摆彩虹（Rainbow）和搭T型积木（T-block）。这些任务涵盖了拾放、操作关节物体、精确执行和长视距多物体装配等技能。使用Claude Code（CC）和Codex作为驱动代理，并测试了它们的不同模型版本（CC-Opus、CC-Fable、Codex-5.5、Codex-5.6-Sol）以评估模型规模和能力扩展性。每个任务进行10个随机初始状态的测试。提供了两种提示变体：“最小提示”仅说明任务目标和成功条件；“详细提示”额外提供一个示例路径点列表作为文本示范。

对比Baseline：由于VIA是一个新范式，论文主要通过比较不同代理和模型版本（代表不同规模和能力的基础模型）来展示性能差异，间接地与依赖微调（VLA）或人工抽象（CaP）的传统范式进行对比。

关键实验结果：

  1. 零样本成功率：在最小提示下，VIA实现了从60%（Codex-5.5）到88%（CC-Fable）的平均成功率，表明现有代理能够零样本将通用能力迁移到机器人控制。CC-Fable在所有任务上表现优异，在LIBERO-Goal的三个任务上达到96.7%成功率，在长视距的彩虹任务上达到100%。
  2. 模型能力扩展性：升级底层模型能直接提升性能。在CC家族中，从Opus 4.8升级到Fable 5，整体成功率从70%提升至88%。在需要精确操作的“将碗放在盘子上”任务中，Codex从GPT-5.5升级到GPT-5.6-Sol，成功率从40%翻倍至80%。
  3. 文本示范的影响：为较弱的CC-Opus提供详细提示（示例路径点列表）后，其在三个LIBERO-Goal任务上的成功率从77%提升至100%。而Codex-5.5未从详细提示中获益。
  4. 任务难度：T-block任务对精度要求极高（容忍约8mm误差），是所有代理面临的最大挑战（成功率10%-40%）。
  5. 效率与成本：在成功的回合中，不同配置的平均工具调用次数在40到84次之间。Codex代理在API成本上有明显优势。

图3：六个评估任务。每个任务的上图展示示例初始状态，下图展示VIA成功运行后的最终状态。物体位置在每次测试中随机化。

消融实验总结：论文通过控制提示的详细程度（最小 vs. 详细）进行了类似消融的实验。结果表明，对于某些代理（如CC-Opus），提供文本形式的“示范”（详细提示）能极大提升性能，这证明了借助VIA框架，通过文本反思或提示优化进行学习的潜力。同时，实验结果也清晰地展示了底层模型能力（不同模型版本对比）对于框架性能的关键贡献。

总结与启发

核心贡献：

  1. 提出了VIA框架，开创了一种无需机器人数据微调、利用现成通用AI代理通过视觉界面控制机器人的新范式。
  2. 展示了如何设计以人类操作为中心、兼顾智能体人体工程学的视觉界面和工具集，使得前沿基础模型的通用能力得以直接迁移。
  3. 通过系统实验证明，该方法的性能与底层基础模型的规模和能力同步扩展，为机器人控制领域利用不断演进的大模型开辟了道路。

局限性：

  1. 在需要极高放置精度的任务（如T-block）中表现不佳。
  2. 目前所有评估均在模拟器中进行，尚未在真实机器人上验证。
  3. 代理的推理和API调用会产生一定的延迟和成本。

对后续研究的启示：

  1. VIA表明机器人控制可以成为另一个具有经济价值的多智能体任务，能够直接从现代模型和代理的进步中受益。
  2. 框架为机器人学习开辟了新方向，例如基于文本或多模态反思的提示优化、跨回合记忆学习、以及由智能体自己提议并实现工具改进的自动工具演化。
  3. 这项工作提示，机器人学研究可以更多地借鉴人机交互和软件工程领域的进展，通过设计更好的“界面”来释放AI的潜力。

💡 一句话总结

本文核心在于探索无需微调前沿视觉语言大模型进行机器人操控的方法。针对传统的视觉-语言-动作模型因数据与算力受限而规模较小、泛化能力不足的问题，提出了VIA框架。它将机器人控制重构为一个智能体任务，让一个现成的基础模型驱动的智能体，通过基于浏览器的3D视觉界面（观测截图、下达直观命令）来操控机械臂，而无需针对特定机器人进行微调。实验表明，该智能体能在多种桌面操作任务上实现零样本执行，在LIBERO-Goal任务上成功率高达96.7%，在一个长视野组装任务上达到100%的成功率，且性能随底层模型能力提升而增强。
